# 백엔드 설계

[문서 목차](../README.md) · 폴더 입구: [backend-node/](../../backend-node/README.md) · 짝: [프론트엔드 설계](../frontend/README.md)

**백엔드 설계는 인증·권한, 거래 데이터의 정합성, 메시지 저장·전달을 다룹니다.** 요청 계층부터 데이터 모델, 트랜잭션, 오류 처리, 소켓, API 계약까지 열 개 문서로 구성했습니다. 현재는 설계 단계이며 서비스 코드는 구현 예정입니다.

## 주요 설계 결정

| 상황 | 처리 방식 | 문서 |
| --- | --- | --- |
| 동시에 같은 요청이 오면? (채팅방 두 번, 등록 재시도, 메시지 재전송) | "있는지 확인 후 생성" 대신 **유니크 제약이 판단**하고, 위반을 잡아 기존 것을 돌려준다 | [03](03-transactions.md) · [05](05-idempotency.md) |
| 삭제 중에 메시지가 오면? | 상품 행을 `FOR SHARE`로 읽어 진행 중인 삭제가 끝난 뒤의 값을 본다 | [03](03-transactions.md) |
| 채팅 목록 · 배지를 인덱스 하나로 처리하려면? | `ChatRoomMember`에 `lastActivityAt`을 복사해 두는 비정규화 — 쓰기 두 행을 더 내고 읽기를 단순하게 | [02](02-data-model.md) |
| 서버가 재시작되면 메시지는? | 소켓은 통로일 뿐, 출처는 DB. 커밋 후 emit, 놓친 건 `after` 커서로 | [09](09-socket-server.md) · [websocket.md](../tech/websocket.md) |
| 남의 채팅방 ID로 요청하면 403인가 404인가? | 비공개 자원은 404 — 403은 존재를 알려 준다 | [04](04-authorization.md) |
