# 01 · 요구사항

[문서 목차](README.md) · 앞: [00 개요](00-overview.md) · [경우의 수](cases/README.md) · 다음: 02 데이터 모델

**이 문서는 "무엇이 되어야 하는가"의 최종본입니다.** 각 기능은 유저 스토리 → 권한 → 수용 조건 순서로 적고, 수용 조건마다 [경우의 수](cases/README.md)의 ID를 달아 근거를 추적합니다. 수용 조건 문장은 그대로 테스트 이름이 됩니다. 여기에 없는 동작은 만들지 않고, 여기 있는 동작은 빠짐없이 만듭니다.

표기: **AC-기능-번호** = 수용 조건. `[케이스 ID]` = 근거. 소켓 동작은 [`websocket.md`](tech/websocket.md) 스파이크로 확인한 뒤 확정했습니다.

## 2. 로그인 · 로그아웃

**유저 스토리** — 가입한 사람으로서, 이메일 · 비밀번호로 들어가서 7일 동안은 다시 묻지 않았으면 한다. 끝나면 로그아웃하고 싶다.

**권한** — 로그인: 비로그인만. 로그아웃: 로그인만.

| AC | 조건 | 근거 |

| AC-LI-01 | 올바른 이메일 · 비밀번호로 `200`과 쿠키를 받고 홈(또는 `next`)으로 이동한다. 토스트는 없다 | LI-OK-01 |
| AC-LI-02 | 이메일 대소문자가 달라도 로그인된다 | LI-OK-02 |

## 9. 마이페이지

**유저 스토리** — 사용자로서, 내가 올린 물건을 상태별로 보고, 산 물건을 확인하고, 닉네임 · 사진 · 비밀번호를 바꾸고 싶다.

**권한** — 로그인. `PATCH /me`는 닉네임 · 아바타만 허용(화이트리스트).

| AC | 조건 | 근거 |
| --- | --- | --- |
| AC-MP-01 | `/me`는 프로필 카드(아바타 · 닉네임 · 이메일 · "YYYY년 M월부터") → [프로필 수정] → 탭(판매중 N · 예약중 N · 거래완료 N · 구매 N) → 목록 → [로그아웃] 순이다 | MP-OK-01, 14 |
| AC-MP-02 | 탭은 `role="tablist"`로 화살표 키 이동이 되고 이름에 개수가 포함되며 `?status=`에 반영된다 | MP-OK-02, MP-A11Y-01, 02 |
| AC-MP-03 | 판매 목록은 삭제된 상품을 제외하고 거래완료 카드에는 "{구매자}님과 거래"가 표시된다 | MP-ST-01, 03 |
| AC-MP-04 | 구매 내역은 `buyerId = me AND status = SOLD`이며 삭제된 상품도 "삭제됨" 라벨로 남는다 | MP-DT-22 |
| AC-MP-05 | 각 탭의 빈 상태 문구가 다르고 판매중 탭에만 [물건 올리기]가 있다 | MP-DT-01~03 |
| AC-MP-06 | 닉네임 변경은 가입과 같은 스키마로 검증하고, 대소문자만 바꾸는 것은 허용하며, 남이 쓰면 `409`다 | MP-IN-01, 03, 04 |
| AC-MP-07 | 닉네임이 바뀌면 헤더 · 채팅 목록 · 메시지 등 모든 곳에서 새 닉네임이 보인다 | MP-IN-06 |
| AC-MP-08 | 아바타는 1장을 클라이언트에서 512px 정사각 중앙 크롭 후 업로드하고 `PATCH /me { avatarUrl }`로 저장하며 이전 파일은 삭제한다. [기본 이미지로]로 되돌릴 수 있다 | MP-OK-08, 09, MP-IM-02, 05 |
| AC-MP-09 | 비밀번호 변경은 현재 · 새 · 확인 세 칸이며 현재가 틀리면 `400 WRONG_PASSWORD`, 새 비밀번호가 현재와 같으면 거부하고, 성공 시 `tokenVersion`이 올라가 다른 세션이 무효화되며 현재 세션은 새 토큰을 받는다 | MP-OK-12, MP-PW-01~04 |
| AC-MP-10 | 프로필 수정 중 변경이 있으면 이탈 확인이 뜬다 | MP-UI-04 |
| AC-MP-11 | `GET /me`는 본인용 사용자 객체와 `counts { onSale, reserved, sold, purchased }`를 돌려준다 | MP-DT-20 |
| AC-MP-12 | `PATCH /me` 본문의 `id · email · role`은 무시된다 | MP-AU-02 |

범위 밖: 남의 프로필, 탈퇴, 설정, 카드에서 상태 변경, 매너온도 · 후기 [MP-OK-04, 11, 13, 15, MP-DT-08, 09].

## 10. 채팅 알림

**유저 스토리** — 사용자로서, 다른 화면에 있어도 새 메시지가 온 걸 알고 한 번에 그 방으로 가고 싶다.

**권한** — 로그인. 알림은 `user:{id}` 룸으로만 전달.

| AC | 조건 | 근거 |
| --- | --- | --- |
| AC-NT-01 | 하단 탭 [채팅] 배지는 **읽지 않은 메시지가 있는 방의 수**이며 `GET /me/unread → { rooms }`와 소켓 `notification:unread { total }`로 유지된다 | 핵심 정의, 결정 0008, NT-DT-01 |
| AC-NT-02 | 계산은 `ChatRoom.lastMessageAt > ChatRoomMember.lastReadAt AND lastMessageSenderId != me`인 방의 수이며 Message 테이블을 조인하지 않는다 | NT-DT-02 |
| AC-NT-03 | `Notification` 테이블은 없다 | 핵심 정의 |
| AC-NT-04 | 로그인 직후 · 포그라운드 복귀 · 소켓 재연결 시 `GET /me/unread`로 배지를 맞춘다 | NT-OK-01, NT-CC-09 |
| AC-NT-05 | 채팅 목록 · 해당 방이 아닌 화면에서 새 메시지가 오면 상대 아바타 · 닉네임 · 1줄 미리보기 토스트가 뜨고, 클릭하면 그 방으로 간다(작성 중 폼이 있으면 이탈 확인 먼저) | NT-OK-02~07 |
| AC-NT-06 | 같은 방의 5초 안 연속 메시지는 "{닉네임}: 메시지 N개" 하나로 합치고, 토스트는 최대 3개까지 쌓인다 | 핵심 정의, NT-CC-01, 02 |
| AC-NT-07 | 방에 들어가 읽으면 배지가 즉시 줄고(낙관적) 내 다른 세션에도 `notification:unread`가 간다 | NT-OK-09, NT-CC-07 |
| AC-NT-08 | 읽지 않은 방이 있으면 브라우저 제목이 `(N) neighbo`다 | NT-OK-11 |
| AC-NT-09 | 삭제 · 거래완료 상품의 방도 배지에 포함된다 | NT-ST-01, 02 |
| AC-NT-10 | 로그아웃 시 배지 0 · 토스트 큐 비움 · 소켓 끊김이다 | NT-ST-04 |
| AC-NT-11 | 탭 접근 가능한 이름은 "채팅, 읽지 않은 대화 N개"이고 토스트는 `role="status"`로 포커스를 뺏지 않으며 상단 중앙(1024px은 우상단)에 뜬다 | NT-A11Y-01~04 |
| AC-NT-12 | `notification:unread`는 서버가 `user:{id}` 룸에만 emit하며 `GET /me/unread`는 분당 60회 제한이다 | NT-SEC-02, 03 |
| AC-NT-13 | 재연결 시 배지만 `GET /me/unread`로 맞추고, 끊긴 동안 온 메시지의 토스트는 띄우지 않는다 | NT-CC-05 |
| AC-NT-14 | 탭이 숨겨진 동안에는 토스트 없이 배지와 탭 제목만 갱신하고, 돌아왔을 때 밀린 토스트를 몰아 띄우지 않는다 | NT-CC-08 |
| AC-NT-15 | 소켓이 끊겨도 별도 폴링을 하지 않는다 | NT-NW-02 |

범위 밖: 알림 목록 화면, 소리 · 진동, Web Push, 이메일, 방별 · 전체 알림 끄기, 상태 변경 알림 [NT-OK-14~19, 알림 종류].
