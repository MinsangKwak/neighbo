# 01 · 회원가입

[문서 목차](../README.md) · 앞: [00 · 공통 — 모든 기능에 걸치는 요구사항과 경우의 수](00-common.md) · 다음: [02 · 로그인 · 로그아웃](02-login.md) · 설계: [흐름](../architecture/flow.md) · [프론트엔드](../architecture/frontend.md) · [백엔드](../architecture/backend.md)

**회원가입은 이메일·비밀번호·비밀번호 확인·닉네임을 입력하고, 성공하면 로그인 상태로 전환하는 흐름입니다.** 1차 범위에는 이메일 인증 메일을 포함하지 않습니다.

## 요구사항

**유저 스토리** — 처음 온 사람으로서, 이메일 · 비밀번호 · 닉네임만으로 계정을 만들고 바로 쓰기 시작하고 싶다.

**권한** — 비로그인만. 로그인 상태면 홈으로.

## 경우의 수

**회원가입은 이메일·비밀번호·비밀번호 확인·닉네임을 입력하고, 성공하면 로그인 상태로 전환하는 흐름입니다.** 1차 범위에는 이메일 인증 메일을 포함하지 않습니다.

### 정상

| ID | 상황 | 기대 동작 (제안) | 결정 |
| --- | --- | --- | --- |
| SU-OK-01 | 네 칸을 모두 올바르게 채우고 제출 | `201` + 쿠키 발급. 토스트 "환영해요, {닉네임}님" 후 홈으로. `?next=`가 있으면 거기로 | — |
| SU-OK-02 | 가입 직후 상태 | 상품 0개, 채팅방 0개, 아바타는 기본 이미지 | — |
| SU-OK-03 | 입력 중 실시간 검증 | 필드를 떠날 때(`blur`) 검증, 오류가 있던 필드는 입력마다 재검증. 제출 전까지 서버 호출 없음 (이메일 중복은 예외 → SU-IN-10) | — |
| SU-OK-04 | 제출 버튼 활성 조건 | 항상 활성. 누르면 전체 검증 후 첫 오류로 포커스. (비활성 버튼은 "왜 안 눌리는지" 모르는 접근성 문제) | — |
