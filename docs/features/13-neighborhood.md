# 13 · 동네

[문서 목차](../README.md) · 앞: [12 · 관심(찜)](12-favorite.md) · 설계: [프론트엔드](../architecture/frontend.md) · [백엔드](../architecture/backend.md)

**동네는 사용자가 목록에서 고르는 값 하나이고, 홈에서 "내 동네만" 볼 수 있게 합니다.** 위치 확인(GPS · 지도 · 인증)은 하지 않습니다. 2차 범위이며, 칸 둘(`User.neighborhood` · `Product.neighborhood`) · 목록 조건 하나 · 프로필 수정의 선택 칸 · 홈의 토글로 이루어집니다.

## 요구사항

**유저 스토리** — 구매자로서, 직접 만나 거래할 수 있는 가까운 곳의 물건만 골라 보고 싶다.

**권한** — 동네를 정하고 바꾸는 것은 본인만. 동네로 거른 목록과 카드의 동네 표시는 누구나 본다.

| AC | 조건 | 프론트가 하는 것 | 백엔드가 하는 것 |
| --- | --- | --- | --- |
| AC-NB-01 | 동네는 서울의 25개 구 가운데 하나이거나 "정하지 않음"이다. 가입 직후에는 정하지 않음이다 | — | `NEIGHBORHOODS`(공유 스키마) · `User.neighborhood` nullable |
| AC-NB-02 | 프로필 수정에서 동네를 고르고 되돌린다. 목록에 없는 값은 저장되지 않는다 | `<select>`(정하지 않음 + 25개). 바뀐 것만 보낸다 | `PATCH /me { neighborhood }` — 이름 또는 `null`. 목록 밖이면 `400 VALIDATION_FAILED`. 생략하면 그대로 둔다 |
| AC-NB-03 | 물건은 올리는 순간 판매자의 동네를 갖는다 | 등록 폼에 칸을 두지 않는다 | 등록 트랜잭션이 `Product.neighborhood`에 판매자의 동네를 적는다 |
| AC-NB-04 | 판매자가 동네를 바꾸면 판매중 · 예약중인 물건이 따라가고, 거래완료된 물건은 그때의 동네로 남는다 | 선택 칸 아래에 그렇게 된다고 적는다 | 프로필 수정과 같은 트랜잭션에서 `status <> 'SOLD'`인 내 물건을 고친다 |
| AC-NB-05 | `GET /products?neighborhood=`는 그 동네의 물건만 돌려주고, 검색어 · 거래완료 숨기기 · 커서와 함께 쓸 수 있다 | 목록 쿼리에 동네 이름을 싣는다 | 조건 추가 + 인덱스 `(neighborhood, deletedAt, createdAt, id)`. 목록 밖 이름이면 `400` |
| AC-NB-06 | 동네를 정한 판매자의 카드 · 상세 · 판매자 프로필에 동네가 보이고, 정하지 않았으면 아무것도 보이지 않는다 | 카드의 상태 줄, 상세의 판매자 줄, 프로필의 가입일 앞 | 카드 · 상세 · 공개 사용자 응답에 `neighborhood`. 없으면 `null`로 읽는다(배포가 엇갈리는 동안) |
| AC-NB-07 | 동네를 정한 사람의 홈에 "내 동네만 (○○구)"가 있고, 켜면 주소에 `?near=1`이 붙어 새로고침 · 뒤로 가기에서 남는다 | 체크박스. 거래완료 숨기기와 같은 부품. 어느 동네인지는 주소가 아니라 로그인한 사람에게서 읽는다 | — |
| AC-NB-08 | 동네를 정하지 않은 로그인 사용자의 홈에는 [내 동네 정하기]가 있고, 손님에게는 둘 다 없다. 동네가 없는 사람이 `?near=1`로 들어오면 전체 목록이다 | 프로필 수정으로 가는 링크 | — |
| AC-NB-09 | 둘러보기 계정은 동네를 바꿀 수 없고, 매일 초기화가 처음 동네로 되돌린다 | 폼 대신 이유를 보인다 [AC-LI-19] | `403 FORBIDDEN` · 초기화 배치가 프로필과 함께 복원 |
| AC-NB-10 | "내 동네만"을 켰는데 물건이 없으면 "○○구에 올라온 물건이 없어요"를 보인다 | 빈 상태 | — |

범위 밖: GPS · 지도 · 동네 인증, 서울 밖 지역과 동 단위, 이웃 동네 묶어 보기, 거리순 정렬, 검색 결과 화면의 동네 조건, 물건마다 동네를 따로 정하기.

## 결정

| 질문 | 결정 | 이유 |
| --- | --- | --- |
| 위치를 확인할까 | 하지 않는다. 목록에서 고른다 | 지도 API와 위치 권한 없이도 "가까운 것만 보기"라는 흐름은 완성된다. 인증이 없으니 동네는 신뢰의 근거가 아니라 거르는 기준일 뿐이다 |
| 직접 적게 할까 | 정해진 목록에서만 | 적게 하면 "마포" · "마포구" · "서울 마포"로 갈려 거르기가 깨진다 |
| 동네를 상품에도 적을까, 판매자에게서 읽을까 | 상품에도 적는다 | 목록을 거를 때 사용자 표를 거치지 않고 인덱스 하나로 읽는다. 끝난 거래가 어디서 있었는지도 남는다 |
| 판매자가 이사하면 올려 둔 물건은 | 판매중 · 예약중은 따라간다 | 물건은 판매자와 함께 있다. 따라가지 않으면 옛 동네 사람에게 계속 보인다 |
| 켠 상태를 어디에 둘까 | 주소(`?near=1`) | 거래완료 숨기기와 같다. 동네 이름을 주소에 싣지 않는 것은, 주소를 받은 다른 사람에게는 그 사람의 동네로 보여야 하기 때문이다 |
| 응답의 동네를 목록 값으로 검증할까 | 문자열로 받는다 | 목록을 줄이는 배포가 나가도 옛 값이 든 응답이 깨지지 않는다. 받는 쪽(입력 · 조회 조건)만 목록으로 검증한다 |
