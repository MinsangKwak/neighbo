# 12 · 관심(찜)

[문서 목차](../README.md) · 앞: [11 · 판매자 프로필](11-seller-profile.md) · 다음: [13 · 동네](13-neighborhood.md) · 설계: [프론트엔드](../architecture/frontend.md) · [백엔드](../architecture/backend.md)

**관심은 다시 보고 싶은 물건에 표시를 남기고 한곳에 모아 보는 기능입니다.** 2차 범위이며, 표 하나(`Favorite`) · API 셋 · 상세의 버튼 하나 · 관심 목록 화면 하나로 이루어집니다.

## 요구사항

**유저 스토리** — 구매자로서, 지금 연락하기는 이르지만 마음에 드는 물건을 표시해 두었다가 나중에 한 번에 보고 싶다.

**권한** — 켜기 · 끄기 · 목록은 로그인한 사람만. 자기 물건에는 켤 수 없다. 개수는 누구나 본다.

| AC | 조건 | 프론트가 하는 것 | 백엔드가 하는 것 |
| --- | --- | --- | --- |
| AC-FV-01 | 켜기는 `PUT /products/{id}/favorite`이고 몇 번을 보내도(동시에 보내도) 한 줄이다 | — | 기본 키 `(userId, productId)` + 중복 무시 삽입. 응답은 바뀐 뒤의 `{ isFavorite, favoriteCount }` |
| AC-FV-02 | 끄기는 `DELETE /products/{id}/favorite`이고 없던 것을 꺼도, 물건이 삭제된 뒤에도 성공이다 | — | 조건 삭제. 상품이 있는지 묻지 않는다 |
| AC-FV-03 | 자기 물건에는 켤 수 없다 | 판매자에게는 버튼을 그리지 않고 개수만 보인다 | `403 FORBIDDEN` |
| AC-FV-04 | 로그인이 없으면 `401`, 없는 물건 · 삭제된 물건에 켜면 `404`다 | 비로그인은 로그인 화면으로 보내고 돌아와 다시 누르게 한다(자동으로 켜지 않는다). `404`면 홈으로 | `401` · `404` |
| AC-FV-05 | 상세는 관심 수(`favoriteCount`)를 누구에게나, 내가 눌렀는지(`viewer.isFavorite`)를 로그인한 사람에게 준다 | 버튼의 처음 상태를 서버가 그려 보낸다 | 상세 조회에 개수와 내 표시 포함. 두 값 모두 없으면 `0` · `false`로 읽는다(배포가 엇갈리는 동안) |
| AC-FV-06 | `/me/favorites`는 내가 누른 물건을 누른 순서의 역순으로 보이고 [더 보기]로 잇는다 | 홈의 목록 부품을 그대로 쓴다. 마이의 [관심 목록]에서 들어간다 | `GET /me/favorites` → `Page<ProductCard>`, 커서는 `(누른 시각, productId)` |
| AC-FV-07 | 삭제된 물건은 관심 목록에서 빠지고, 거래완료된 물건은 흐리게 남는다 | 카드의 거래완료 표시는 홈과 같다 | 목록 조회에 `product.deletedAt IS NULL` |
| AC-FV-08 | 버튼은 누르는 즉시 모양과 개수가 바뀌고, 실패하면 되돌리고 이유를 알린다. 응답을 기다리는 동안의 연타는 버린다 | 낙관적 갱신 · 되돌리기 · 토스트. 이름은 "관심 {개수}", 상태는 `aria-pressed`, 크기 44px 이상 | 사용자 분당 30 |
| AC-FV-09 | 데모 계정이 눌러 둔 관심은 매일 초기화에서 지워진다 | — | 초기화 배치가 데모 계정의 `Favorite`을 삭제 |
| AC-FV-10 | 관심 목록이 비어 있으면 "관심 목록이 비어 있어요"와 [물건 보러 가기]를 보인다 | 빈 상태 | — |

범위 밖: 목록 카드의 관심 수 · 하트, 관심 물건의 가격 · 상태가 바뀌었을 때 알림, 판매자가 누가 눌렀는지 보기, 관심 수 정렬.

## 결정

| 질문 | 결정 | 이유 |
| --- | --- | --- |
| 켜기 · 끄기를 한 주소의 토글(`POST`)로 둘까 | `PUT`과 `DELETE`로 나눈다 | 토글은 응답을 못 받고 다시 보내면 반대로 뒤집힌다. 나눠 두면 같은 요청이 두 번 가도 결과가 같다 |
| 개수를 `Product`에 숫자로 둘까 | 두지 않고 셀 때마다 센다 | 상세에서만 쓰고, `Favorite(productId)` 인덱스로 센다. 숫자를 따로 두면 켜기 · 끄기마다 두 표를 함께 맞춰야 한다 |
| 물건이 삭제되면 관심 줄을 지울까 | 지우지 않는다. 목록에서만 뺀다 | 삭제는 soft이고 사진 정리 뒤에도 상품 줄은 남는다. 줄을 남겨 두어도 보이는 곳이 없다 |
| 계정이나 상품 줄이 실제로 지워지면 | 관심 줄도 함께 지워진다 (`ON DELETE CASCADE`) | 샘플 데이터를 지울 때 걸리지 않게 |
| 목록 카드에 하트를 둘까 | 두지 않는다 | 카드는 전체가 링크 하나다 [AC-PL-05]. 안에 버튼을 넣으면 그 규칙이 깨진다 |
