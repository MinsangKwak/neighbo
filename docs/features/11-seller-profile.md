# 11 · 판매자 프로필

[문서 목차](../README.md) · 앞: [10 · 채팅 알림](10-notification.md) · 설계: [프론트엔드](../architecture/frontend.md) · [백엔드](../architecture/backend.md)

**판매자 프로필은 한 사람이 올린 물건을 모아 보는 공개 화면입니다.** 1차 범위(열 가지 기능)에서 빼 두었던 것을 2차로 더했고, 새 화면 하나 · 조회 API 하나 · 기존 목록 API의 조건 하나로 이루어집니다.

## 요구사항

**유저 스토리** — 구매자로서, 물건을 올린 사람이 다른 무엇을 팔고 얼마나 거래했는지 보고 연락할지 정하고 싶다.

**권한** — 누구나(비로그인 포함). 고치는 기능은 없다 — 본인은 [마이페이지](09-mypage.md)에서 고친다.

| AC | 조건 | 프론트가 하는 것 | 백엔드가 하는 것 |
| --- | --- | --- | --- |
| AC-UP-01 | `/users/{id}`는 로그인 없이 열리고 아바타 · 닉네임 · 가입한 달 · 상태별 개수(판매중 · 예약중 · 거래완료) · 올린 물건 목록을 보인다 | 서버에서 프로필과 첫 20개를 그려 보낸다. 제목 구조는 h1 "프로필" → h2 닉네임 · h2 "올린 물건" | `GET /users/{id}` → `{ user, counts }` |
| AC-UP-02 | 이메일과 구매 수는 어디에도 나오지 않는다 | — | 응답은 `UserPublic`과 판매 개수 셋뿐이다. 구매 수는 `GET /me`에만 있다 |
| AC-UP-03 | 목록은 그 판매자의 물건만 최신순이며 [더 보기] · [거래완료 숨기기]가 홈과 같게 동작한다 | 홈의 목록 부품을 그대로 쓴다. 숨기기 상태는 주소(`?hideSold=1`)에 둔다 | `GET /products?sellerId=` — 다른 조건(`hideSold` · `cursor`)과 함께 쓴다 |
| AC-UP-04 | 상세 화면의 판매자 영역을 누르면 프로필로 간다 | 영역 전체가 링크, 이름은 "판매자 {닉네임}", 높이 44px 이상 | — |
| AC-UP-05 | 삭제한 물건은 목록과 개수에서 빠진다 | — | 목록은 자동 주입, 개수는 `deletedAt IS NULL`을 직접 건다 |
| AC-UP-06 | 없는 사용자는 "찾을 수 없어요" 화면이다 | `notFound()` | `404 NOT_FOUND` |
| AC-UP-07 | 본인이 자기 프로필을 보면 [마이로 가기]가 있다. 남에게는 없다 | 세션의 id와 비교 | — |
| AC-UP-08 | 올린 물건이 없으면 "올린 물건이 없어요", 숨기기로 다 가려졌으면 "거래 중인 물건이 없어요"다 | 빈 상태 문구 분기. 물건이 하나도 없으면 숨기기 체크박스를 그리지 않는다 | — |

범위 밖: 거래 후기 · 매너 점수, 판매자 차단 · 신고, 채팅방에서 프로필로 가는 길, 프로필 공유.

## 결정

| 질문 | 결정 | 이유 |
| --- | --- | --- |
| 목록을 새 API로 둘까, 기존 목록에 조건을 더할까 | `GET /products`에 `sellerId` 조건 | 커서 · 숨기기 · 카드 모양이 같다. 화면도 홈의 목록 부품을 그대로 써서 [더 보기] 뒤 포커스 이동 같은 동작이 따라온다 |
| 상태를 탭으로 나눌까 | 나누지 않는다. 개수는 숫자로, 목록은 한 줄로 | 카드에 상태 배지가 이미 있다. 탭은 본인이 관리하는 마이페이지의 것이다 |
| 구매 수를 보일까 | 보이지 않는다 | 무엇을 샀는지는 본인만 아는 정보다 [결정 0012](../decisions.md) |
| 데모 · 샘플 계정의 프로필 | 다른 계정과 같게 열린다 | 가릴 정보가 없다 |
