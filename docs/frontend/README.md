# 프론트엔드 설계

[문서 목차](../README.md) · 폴더 입구: [frontend-next/](../../frontend-next/README.md) · 짝: [백엔드 설계](../backend/README.md)

**프론트엔드는 "서버가 정한 규칙을 사용자가 이해할 수 있는 화면으로 바꾸는" 역할입니다.** 권한 · 무결성은 백엔드가 강제하므로, 프론트가 고민하는 것은 다른 축입니다 — 어디서 그리나(01), 데이터의 주인은 누구인가(02), 무엇을 바꾸면 어느 화면이 깨지나(03), 실패를 얼마나 좁게 받나(04), 입력을 어떻게 돕나(05), 화면이 바뀔 때 누구에게 무엇을 알리나(06), 연결이 흔들릴 때 무엇을 지키나(07).

## 가장 오래 고민한 다섯 가지

| 고민 | 결론 | 문서 |
| --- | --- | --- |
| 판매자에게 보인 화면이 다른 사람에게 보이면? | 서버 렌더의 모든 백엔드 호출을 `no-store`로 강제하는 함수 하나 | [01](01-rendering.md) |
| 메시지가 실패했는데 상대에겐 도착하면? | 타임아웃 없는 emit을 lint로 금지, 끊긴 동안은 우리 대기열 | [07](07-socket-client.md) · [websocket.md](../tech/websocket.md) |
| 상품 하나를 바꿨는데 어느 화면이 옛 값을 보여주나? | 쓰기 × 캐시 키 무효화 지도를 먼저 정함 | [03](03-cache.md) |
| 실패한 메시지 · 대기 중인 메시지를 어디에 두나? | 서버 캐시에 섞지 않고 대기열에 따로, 그릴 때 합침 | [02](02-state.md) |
| 스크린리더 사용자는 새 메시지 · 페이지 이동을 어떻게 아나? | 경로 이동은 `h1` 포커스, 메시지는 상대 것만 별도 리전 | [06](06-focus.md) |
