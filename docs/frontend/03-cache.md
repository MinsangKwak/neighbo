# 프론트 03 · 캐시와 낙관적 갱신

[프론트엔드 설계](README.md) · 앞: [02 상태 소유권](02-state.md) · 다음: [04 에러 경계](04-errors.md)

**쓰기 작업과 소켓 이벤트별로 갱신해야 할 캐시를 미리 정의했습니다.** 상품이나 메시지가 변경된 뒤 관련 화면에 이전 값이 남지 않도록 키와 무효화 범위를 함께 관리합니다. 이 표는 [변경 영향 매트릭스](../00-overview.md#24-변경-영향-매트릭스)를 프론트엔드 캐시에 적용한 설계입니다.

## 1. 캐시 키

키는 `queryKeys.ts` 한 파일에서만 만든다. 문자열을 직접 쓰면 오타 하나로 무효화가 조용히 실패한다.

| 키 | 데이터 | 종류 | `staleTime` | 서버 렌더 하이드레이트 |
| --- | --- | --- | --- | --- |
| `['me']` | 내 정보 + 개수 | 단건 | 5분 | 루트 레이아웃 |
| `['me', 'unread']` | 읽지 않은 방 수 | 단건 | ∞ (소켓이 갱신) | 탭 레이아웃 |
| `['me', 'products', status]` | 판매 탭 목록 | 무한 | 30초 | 마이 |
| `['me', 'purchases']` | 구매 내역 | 무한 | 30초 | 마이 |
| `['products', { q, hideSold }]` | 홈 · 검색 목록 | 무한 | 30초 | 홈 · 검색 |
| `['product', id]` | 상세 | 단건 | 30초 | 상세 · 수정 |
| `['product', id, 'chatPartners']` | 거래완료 바텀시트 목록 | 단건 | 0 (열 때마다) | — |
| `['chatRooms', { productId }]` | 채팅 목록 | 무한 | ∞ (소켓이 갱신) | 채팅 목록 |
| `['chatRoom', id]` | 방 · 상품 요약 · 상대 `lastReadSeq` | 단건 | ∞ (소켓이 갱신) | 채팅방 |
| `['messages', roomId]` | 메시지 (과거 방향 무한) | 무한 | ∞ (소켓이 갱신) | 채팅방 |

`staleTime ∞`인 키는 소켓 이벤트로만 갱신되므로, **소켓이 끊겼다 붙으면 반드시 재조회**한다 ([07 소켓 클라이언트](07-socket-client.md)). 이걸 빼먹으면 끊긴 동안의 변화가 영영 반영되지 않는다.

## 2. 캐시 갱신 범위

✏️ 응답으로 직접 갱신 · ♻️ 무효화(다시 가져옴) · ✂️ 캐시에서 제거

| 쓰기 | `product` | `products` | `me` | `me/products` | `me/purchases` | `chatRooms` | `chatRoom` | `messages` | `me/unread` |
| --- | --- | --- | --- | --- | --- | --- | --- | --- | --- |
| 상품 등록 | ✏️ 새 상품 | ♻️ | ♻️ 개수 | ♻️ 판매중 | | | | | |
| 상품 수정 | ✏️ | ♻️ | | ♻️ 해당 탭 | | ♻️ (요약 가격 · 제목) | ♻️ 이 상품 방들 | | |
| 상태 변경 | ✏️ | ♻️ | ♻️ 개수 | ♻️ 전 탭 | | ♻️ (썸네일 배지) | ♻️ | | |
| 상품 삭제 | ✂️ | ✂️ 해당 항목 | ♻️ 개수 | ♻️ | | ♻️ ("삭제됨") | ♻️ | | |
| 채팅방 만들기 | ♻️ (`existingChatRoomId`) | | | | | ♻️ | ✏️ | | |
| 메시지 전송 (ack) | | | | | | ✏️ 행 맨 위로 | ✏️ 마지막 메시지 | ✏️ 추가 | |
| 읽음 | | | | | | ✏️ 행 배지 0 | | | ✏️ 낙관적 −1 |
| 닉네임 · 아바타 변경 | | | ✏️ | | | | | | |
| 로그인 · 로그아웃 | 전체 `queryClient.clear()` | | | | | | | | |

다른 사용자의 화면(예: 내가 거래완료로 바꿨을 때 구매자의 구매 내역)은 프론트가 고칠 수 없다. 그쪽은 다음 조회 · 포커스 복귀 · 소켓 이벤트가 맞춘다 [CM-CC-02].

### 소켓 이벤트 → 캐시

| 이벤트 | 갱신 |
| --- | --- |
| `message:new` | `messages` 추가(같은 `id` 있으면 무시) · `chatRooms` 행 맨 위로 + 미리보기 · 그 방을 보고 있지 않으면 행 배지 +1 |
| `room:read` (상대) | `chatRoom`의 상대 `lastReadSeq` → "읽음" 표시 |
| `room:read` (내 다른 탭) | `chatRooms` 행 배지 0 |
| `notification:unread` | `me/unread` = `total` |
| `room:product_updated` | `chatRoom`의 상품 요약 · `product` 무효화 · `chatRooms` 행 |
| 재연결 | `me/unread` · `chatRooms` · 열린 방의 `chatRoom` 무효화 + 방마다 `room:join { after }` |

`chatRooms` 재정렬은 100ms 디바운스로 묶는다 [AC-CL-05].

## 3. 낙관적 갱신 — 쓰는 곳과 안 쓰는 곳

**세 조건을 모두 만족할 때만 낙관적으로 갱신합니다.** ① 서버가 거절할 일이 드물다 ② 거절됐을 때 되돌림이 눈에 보이고 이해된다 ③ 다음 단계에 서버가 만든 값(새 id 등)이 필요 없다.

| 작업 | 낙관적? | 이유 | 실패하면 |
| --- | --- | --- | --- |
| 메시지 전송 | ✅ | 즉시 보여야 대화가 된다. `tempId`로 그리고 ack로 확정 | 말풍선을 지우지 않고 "전송 실패 [재시도] [삭제]" — 쓴 글을 잃지 않게 [AC-CH-04] |
| 방 입장 시 배지 −1 | ✅ | 서버가 거절할 일이 거의 없음 | 재조회로 복구 [AC-NT-07] |
| 상태 `<select>` | ✅ | 선택한 값이 바로 보여야 함 | 이전 값으로 되돌리고 토스트 [AC-PD-08] |
| 상품 등록 · 수정 | ❌ | 성공해야 상세로 이동, 새 id 필요, 실패 시 폼을 유지해야 함 | 폼 유지 + 오류 |
| 상품 삭제 | ❌ | 되돌림이 이해하기 어려움 (사라졌다 다시 나타남) | 모달 유지 + 토스트 |
| 채팅방 만들기 | ❌ | 방 id가 있어야 이동 | 버튼 복구 + 토스트 |
| 닉네임 변경 | ❌ | 중복으로 거절될 수 있음 | 칸 오류 |
| 거래완료 + 구매자 지정 | ❌ | 구매자 검증에서 거절될 수 있고, 되돌림 시 바텀시트 상태가 꼬임 | 바텀시트 유지 + 오류 |

## 4. 재시도 정책

| 종류 | 자동 재시도 | 이유 |
| --- | --- | --- |
| 조회 | 네트워크 오류 · 5xx에 1번 (1초 뒤) | 순간 끊김은 한 번이면 대부분 회복 |
| 조회 4xx | 안 함 | 다시 해도 같다 |
| 쓰기 | 안 함 — 사용자가 누른다 | 서버에 닿았는지 모름 [AC-CM-22]. 재시도가 안전한 쓰기는 백엔드가 멱등키로 보장 ([백엔드 05](../backend/05-idempotency.md)) |
| 포커스 복귀 | `refetchOnWindowFocus` — `staleTime`이 지난 것만 | 다른 탭 · 다른 기기의 변화 반영 |
