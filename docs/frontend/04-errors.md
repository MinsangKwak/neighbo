# 프론트 04 · 에러 경계

[프론트엔드 설계](README.md) · 앞: [03 캐시](03-cache.md) · 다음: [05 폼](05-forms.md) · 코드 목록: [백엔드 06 에러 코드](../backend/06-errors.md)

**에러는 "얼마나 넓게 망가졌나"에 따라 세 겹에서 받습니다 — 앱 전체 · 페이지 · 영역.** 좁게 받을수록 사용자가 잃는 것이 적습니다. 목록 하나가 실패했다고 헤더와 탭바까지 사라지면 안 되고, 메시지 하나가 실패했다고 채팅방 전체가 에러 화면이 되면 안 됩니다.

## 1. 세 겹

| 겹 | Next.js 파일 · 위치 | 받는 것 | 보이는 것 | 남는 것 |
| --- | --- | --- | --- | --- |
| 앱 | `app/global-error.tsx` | 루트 레이아웃 자체의 렌더 실패 | 최소 화면 "일시적인 문제가 생겼어요" + [새로고침] | 없음 (레이아웃까지 실패) |
| 페이지 | 경로마다 `error.tsx` · `not-found.tsx` | 페이지 서버 렌더 실패 · `notFound()` | 본문 자리에 에러 · 404 | 헤더 · 탭바 [AC-CM-21, 23] |
| 영역 | 컴포넌트 안 (쿼리 · 뮤테이션 결과) | [더 보기] 실패 · 이미지 실패 · 전송 실패 · 폼 제출 실패 | 그 자리에 문구 + [다시 시도] | 화면 나머지 전부 [AC-PL-15, AC-CH-04] |

**판단 기준**: 이 데이터 없이 페이지가 의미가 있나? 상품 상세에서 상품이 없으면 페이지 에러(404), 사진 한 장이 없으면 영역(플레이스홀더), 채팅방에서 첫 메시지 로드가 실패하면 본문 영역(입력창 비활성) [CH-NW-01].

## 2. API 클라이언트 — 에러를 한 모양으로

모든 요청은 `apiFetch()`를 지난다. 서버 응답 · 네트워크 실패 · 타임아웃을 모두 `ApiError` 하나로 바꿔서, 화면 코드는 `error.code`만 보면 된다.

```ts
class ApiError extends Error {
  status: number;        // 0 = 네트워크 · 타임아웃
  code: ErrorCode | 'NETWORK' | 'TIMEOUT';
  fields?: Record<string, string>;
  requestId?: string;    // 응답 헤더 X-Request-Id
  retryAfter?: number;   // 429
}
```

| 상황 | 변환 |
| --- | --- |
| 서버 에러 응답 | 본문의 `error.code` · `fields` + 헤더의 요청 ID |
| `fetch`가 던짐 (오프라인 · DNS) | `code: 'NETWORK'` |
| 10초 초과 (`AbortController`) | `code: 'TIMEOUT'` [CM-NW-01] |
| JSON 파싱 실패 | `code: 'INTERNAL'` [CM-NW-07] |

## 3. 전역 처리 — 화면이 신경 쓰지 않아도 되는 것

TanStack Query의 전역 `onError`에서 처리하고, 화면은 자기 영역의 표시만 한다.

| 코드 | 전역 처리 | 예외 |
| --- | --- | --- |
| `UNAUTHORIZED` | 캐시 비우기 → `/login?next=현재경로` | 로그인 화면 자신 (무한 이동 방지) |
| `RATE_LIMITED` | 토스트 "잠시 후 다시 시도해 주세요", 그 버튼을 `retryAfter`초 비활성 | — [AC-CM-26] |
| `INTERNAL` · 5xx | 토스트 "일시적인 문제가 생겼어요 (문의 번호 a1b2c3)" | 페이지 렌더 실패면 페이지 겹이 받음 |
| `NETWORK` · `TIMEOUT` | 영역에 "불러오지 못했어요 [다시 시도]" | 쓰기면 토스트 "저장하지 못했어요. 다시 시도해 주세요" + 입력 유지 [AC-CM-22] |
| `FORBIDDEN` | 토스트 "권한이 없어요" → 이전 화면 | — [CM-NW-09] |

`INVALID_CREDENTIALS`는 401이지만 코드가 달라서 전역 401 처리를 타지 않는다 — 백엔드가 코드를 나눈 이유다 ([백엔드 06](../backend/06-errors.md#코드를-나누고-합친-판단)).

## 4. 화면이 직접 처리하는 코드

| 코드 | 어디서 | 반응 | 근거 |
| --- | --- | --- | --- |
| `VALIDATION_FAILED` | 모든 폼 | `fields`를 각 칸 아래에, 상단 요약 `role="alert"`, 첫 오류로 포커스 | AC-SU-17, 18 |
| `EMAIL_TAKEN` · `NICKNAME_TAKEN` | 가입 · 프로필 | 해당 칸 오류 (이메일은 [로그인하기] 링크) | AC-SU-07, 14 |
| `INVALID_CREDENTIALS` | 로그인 | 폼 상단 오류, 비밀번호 칸 비우고 포커스 | AC-LI-07 |
| `WRONG_PASSWORD` | 비밀번호 변경 | 현재 비밀번호 칸 오류 | AC-MP-09 |
| `INVALID_TRANSITION` | 상세 상태 `<select>` | 이전 값으로 되돌림 + 토스트 + 상품 재조회 | AC-PD-08 |
| `PRODUCT_SOLD` | 상세 [채팅하기] | 토스트 + 상품 재조회 (버튼이 비활성으로 바뀜) | AC-PD-20 |
| `NOT_FOUND` (작업 중) | 수정 저장 · 채팅하기 · 삭제 | 토스트 "삭제된 물건이에요" → 홈. **삭제 요청에 대한 404는 성공으로** | AC-PC-35, PX-NW-01 |
| `NOT_A_CHAT_PARTNER` | 거래완료 바텀시트 | 목록 재조회 | AC-PD-05 |
| `INVALID_FILE` · `UNSUPPORTED_IMAGE` · `PAYLOAD_TOO_LARGE` | 업로드 | 해당 썸네일 오류 (재시도는 `INVALID_FILE`만) | AC-PC-15 |
| `INVALID_CURSOR` | 목록 | 사용자에게 안 보이게 첫 페이지부터 | AC-PL-04 |
| 소켓 `PRODUCT_DELETED` | 채팅방 | 말풍선 실패 + 입력창 비활성 | AC-PX-08 |

## 5. 사용자가 보는 문장

| 규칙 | 이유 |
| --- | --- |
| 서버 `message`를 기본으로 쓰되, 화면 맥락에 더 맞는 문구가 있으면 프론트 문구 | 서버 문구는 맥락을 모른다 (같은 `NOT_FOUND`라도 상세에선 404 화면, 저장 중엔 "삭제된 물건이에요") |
| "무엇이 · 왜 · 무엇을 할 수 있나" — [다시 시도] · [홈으로] 같은 다음 행동을 함께 | 막다른 화면 금지 |
| 5xx에는 문의 번호(요청 ID 앞 6자) | 사용자가 말해 주면 로그 한 줄로 찾는다 ([백엔드 08](../backend/08-observability.md)) |
| 에러 토스트는 `role="alert"`, 페이지 에러는 `h1`으로 포커스 | [06 포커스](06-focus.md) |

## 6. 배포 직후의 청크 오류

배포로 파일 이름이 바뀌면 열려 있던 탭이 옛 청크를 요청해 404가 난다 [CM-NW-12]. 전역 에러 경계에서 `ChunkLoadError`를 알아보고 "새 버전이 있어요 [새로고침]"을 보여준다. 폼 작성 중이면 자동 새로고침하지 않는다 — 사용자가 쓴 내용을 잃게 된다.
