# 문서 목차

**공통 문서를 먼저 읽고, 그 다음 역할별 설계로 갈라집니다.** 공통 문서는 "무엇이 되어야 하는가", 역할 문서는 "각 역할이 그것을 어떻게 맡는가"를 답합니다. 뒤 문서는 앞 문서에 의존합니다.

## 공통

| 순서 | 문서 | 답하는 질문 | 상태 |
| --- | --- | --- | --- |
| 00 | [개요](00-overview.md) | 무엇을, 왜, 어디까지 만드는가 · 서비스 전체 지도 | 작성 |
| 00+ | [경우의 수](cases/README.md) | 기능마다 일어날 수 있는 모든 상황과 그때의 동작 (01의 입력) | 작성 — 결정 필요 0건 |
| 01 | [요구사항](01-requirements.md) | 각 기능은 누가 · 언제 · 어떤 조건에서 어떻게 동작하는가 — 수용 조건 251개, 조건마다 프론트 · 백엔드 역할 | 작성 |

## 문서 작성 원칙

- **결론 먼저.** 각 문서와 절의 첫 문장은 굵은 글씨로 결론을 적습니다.
- **결정과 제안을 구분합니다.** 확정되지 않은 것은 "제안" 또는 "확정 필요"로 표시합니다.
- **빈 상태 · 에러 상태를 빠뜨리지 않습니다.** 정상 흐름만 적은 명세는 반쪽입니다.
- **문서가 바뀌면 같은 PR에서 고칩니다.** 코드와 문서가 어긋난 채로 병합하지 않습니다.
