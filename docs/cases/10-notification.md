# NT · 채팅 알림

[경우의 수 목차](README.md) · 공통: [00-common.md](00-common.md) · 앞: [08-chat.md](08-chat.md)

**새 메시지가 오면 앱 안에서 세 곳이 바뀝니다 — 하단 탭 [채팅] 배지(읽지 않은 방 수 또는 메시지 수) · 채팅 목록 순서 · 현재 화면의 토스트.** 브라우저 푸시 · 이메일 · 소리는 1차 범위 밖입니다. 알림은 별도 테이블 없이 `lastReadAt`에서 계산합니다(❓ 아래).

## 핵심 정의 (제안)

| 항목 | 제안 | 결정 |
| --- | --- | --- |
| 배지 숫자의 의미 | **읽지 않은 메시지가 있는 방의 수** (메시지 총수 아님). 방 3개에 메시지 50개면 "3". 방 단위가 행동(어느 방에 들어갈지)과 일치 | ❓ 메시지 수 vs 방 수 |
| 알림 저장 | `Notification` 테이블 **없음.** 배지 = `COUNT(room WHERE 상대 메시지 createdAt > 내 lastReadAt)`. 알림 목록 화면이 없으므로 저장할 이유가 없음 | ❓ |
| 알림 종류 | 새 메시지 하나뿐. 상태 변경 · 거래완료 지정 알림은 1차 없음 | ❓ |
| 전달 경로 | 소켓 `notification:unread { total }` (서버가 메시지 저장 후 수신자의 모든 세션에 push) + 앱 진입 · 포커스 복귀 시 HTTP `GET /me/unread` | — |
| 토스트 | 채팅 목록 · 해당 채팅방이 **아닌** 화면에 있을 때만. 내용: 상대 아바타 · 닉네임 · 메시지 1줄. 클릭 시 그 방으로. 5초 자동 소멸 | ❓ |
| 토스트 억제 | 같은 방에서 5초 안에 연속 메시지면 토스트 하나로 합침 "{닉네임}: 메시지 N개" | — |

| NT-CC-04 | 한 탭이 방을 읽는 순간 다른 탭에 토스트가 뜨던 중 | 다른 탭은 `notification:unread`로 배지는 줄지만 이미 뜬 토스트는 유지 (허용) | — |
| NT-CC-05 | 소켓 끊긴 동안 메시지 도착 | 재연결 시 `GET /me/unread` 재조회로 배지 맞춤. 끊긴 동안의 토스트는 **띄우지 않음** (몰아서 뜨면 방해) | ❓ |
| NT-CC-06 | 재연결 시 `notification:unread`와 HTTP 재조회가 다른 값 | 나중에 도착한 값. 둘 다 서버 계산이라 같아야 정상 | — |
| NT-CC-07 | 배지 낙관적 갱신 (방 입장 즉시 −1) 후 `room:read` 실패 | 재조회로 복구. 낙관적 갱신은 함 | — |
| NT-CC-08 | 백그라운드 탭에서 메시지 도착 | 소켓이 살아 있으면 배지 · 제목 갱신. 토스트는 포그라운드 복귀 시 **최신 1개만** | ❓ |
| NT-CC-09 | 포그라운드 복귀 | `visibilitychange` → 연결 확인 → `GET /me/unread` | — |
