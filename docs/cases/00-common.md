# CM · 공통 — 모든 기능에 걸치는 경우의 수

[경우의 수 목차](README.md)

**기능 문서에서 반복되는 상황은 여기 한 번만 적고, 기능 문서는 ID로 참조합니다.** 여기서 정한 동작은 모든 화면 · 모든 API에 같은 방식으로 적용됩니다.

## 인증 · 세션

| ID | 상황 | 기대 동작 (제안) | 결정 |
| --- | --- | --- | --- |
| CM-AU-01 | 로그인이 필요한 화면에 비로그인으로 URL 직접 접근 | 로그인 화면으로 이동. 로그인 성공 후 원래 가려던 URL로 돌아온다 (`?next=` 쿼리). 안내 문구 "로그인이 필요한 페이지예요" 토스트 | — |
| CM-AU-02 | 로그인이 필요한 API를 비로그인으로 호출 | `401`. 응답 본문 `{ error: { code: "UNAUTHORIZED" } }`. 프론트는 전역 인터셉터에서 CM-AU-01과 같이 처리 | — |
| CM-AU-03 | 화면을 열어 둔 채 세션(JWT)이 만료됨 | 다음 API 호출에서 `401` → 로그인 화면으로. 작성 중이던 폼 내용은 잃는다 (❓ 로컬에 임시 저장할지) | ❓ |
| CM-AU-04 | JWT 만료 시간 | 제안: 액세스 토큰 7일, 리프레시 없음. 7일 안에 활동이 있으면 응답마다 새 쿠키로 연장(슬라이딩) | ❓ |
| CM-AU-05 | 쿠키가 조작되거나 서명이 틀림 | `401`. 쿠키 삭제 헤더 포함 | — |
| CM-AU-06 | 토큰은 유효하지만 사용자가 DB에서 사라짐(탈퇴 등) | `401`. 탈퇴는 1차 범위 밖이지만 서버는 이 경우를 처리한다 | — |
| CM-AU-07 | 두 브라우저에서 같은 계정으로 로그인 | 둘 다 유효. 동시 세션 제한 없음 | — |
| CM-AU-08 | 한쪽에서 로그아웃 | 그 브라우저의 쿠키만 삭제. 다른 브라우저는 유지 (stateless JWT라 서버에서 무효화 불가) | — |
| CM-AU-09 | 로그인 상태에서 로그인 · 회원가입 화면 접근 | 홈(중고 목록)으로 이동 | — |
| CM-AU-10 | 서버가 재시작되어 JWT 비밀키가 바뀜 | 모든 사용자가 `401` → 재로그인. 비밀키는 환경 변수로 고정해 재시작에도 유지한다 | — |

## 에러 응답 형식 (서버 공통)

| ID | 상황 | 기대 동작 (제안) | 결정 |
| --- | --- | --- | --- |
| CM-ER-01 | 모든 에러 응답의 모양 | `{ error: { code: string, message: string, fields?: { [name]: string } } }`. `code`는 대문자 스네이크, `message`는 한국어 사용자 문구, `fields`는 폼 검증 실패 시 필드별 문구 | — |
| CM-ER-02 | 검증 실패 (`400`) | `code: "VALIDATION_FAILED"`, `fields`에 실패한 필드 전부(첫 번째만이 아님) | — |
| CM-ER-03 | 성공 응답의 모양 | 본문에 자원을 그대로 (`{ product: {...} }`), 래퍼 `data` 없음. 목록은 `{ items: [], nextCursor: string \| null }` | ❓ |
| CM-ER-04 | 서버가 예상 못 한 예외 | `500`, `code: "INTERNAL"`, 스택은 로그에만. 요청 ID를 응답 헤더 `X-Request-Id`로 내려 문의 시 추적 | — |

| CM-SEC-03 | 다른 사용자의 ID를 URL · 본문에 넣어 요청 | 서버는 항상 토큰의 사용자 ID를 쓴다. 본문의 `userId`는 무시 | — |

| CM-SEC-05 | 메시지 · 상품 등록 반복 | 사용자당 분당 30회(`429`) | ❓ |

| CM-SEC-08 | 에러 메시지로 계정 존재 여부 유추 (로그인 실패 시 "이메일 없음" vs "비밀번호 틀림") | 로그인 실패는 항상 같은 문구. 회원가입 중복 검사는 별개(LI 문서 참조) | — |
| CM-SEC-09 | HTTPS 아닌 접속 | 운영은 플랫폼이 HTTPS 강제. 쿠키 `Secure` | — |
| CM-SEC-10 | 아주 큰 요청 본문 (수 MB JSON) | `413`. 본문 한도 1MB, 이미지 업로드는 별도 한도 | — |
