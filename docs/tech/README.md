# 기술 노트 · 동작 원리와 실험 결과

[문서 목차](../README.md) · [00 개요](../00-overview.md) · [결정 기록](../decisions/README.md)

**기술 노트는 서비스에 필요한 동작과 실험에서 확인한 결과를 기록합니다.** 사용 목적, 동작 원리, 최소 구현, 적용 방식, 문제 원인을 구분합니다. 현재 WebSocket 노트와 스파이크 6개가 있으며, 다른 항목은 아래 표의 계획 단계입니다.

## 기록 항목

| 항목 | 내용 |
| --- | --- |
| 사용 목적 | 필요한 서비스 동작과 대안. 관련 [결정 기록](../decisions/README.md) 연결 |
| 동작 원리 | 요청·연결·데이터 처리 순서 |
| 최소 구현·실험 | 실행 코드, 관찰 결과, 라이브러리가 담당하는 범위 |
| 적용 방식 | 서비스에 적용할 설정·인터페이스·처리 규칙 |
| 문제 원인 | 증상, 가설, 확인 방법, 원인, 수정, 재발 방지 |

실험 결과와 적용 계획은 별도로 표시합니다. 구현·테스트 중 확인한 내용은 해당 노트와 문제 기록에 추가합니다.

## 실험 코드 관리

- 재현 가능한 코드는 `spikes/`에서 서비스와 분리해 관리합니다.
- 실행 조건, 관찰 결과, 확인하지 못한 범위를 노트에 함께 기록합니다.
- 결과에 따라 설계가 달라지면 [결정 기록](../decisions/README.md)과 관련 명세를 갱신합니다.

## 원인 노트 형식 (5절)

```markdown
### YYYY-MM-DD · 한 줄 증상
- 증상: 무엇이 보였나 (에러 메시지 · 화면 · 재현 조건)
- 가설: 처음 의심한 것
- 확인: 어떻게 확인했나 (로그 · 쿼리 · 실험)
- 원인: 실제 원인 — 기술의 어떤 동작 때문인가
- 수정: 무엇을 바꿨나 (커밋 링크)
- 재발 방지: 테스트 · lint · 문서 중 무엇을 추가했나
```

원인과 확인 방법이 아직 밝혀지지 않은 항목은 미확인 상태로 남깁니다.
