# 0011 · 목록 · 상세는 비로그인으로 볼 수 있다

| 상태 | 결정 2026-11-09 |
| --- | --- |
| 영향 | 중고 목록 · 검색 · 거래 상세 · OG 메타 · 인증 미들웨어의 선택적 인증 |

## 맥락

당근은 앱이라 로그인이 전제지만, 웹은 링크를 공유하고 검색에 걸리는 매체다. 비로그인 사용자가 상품을 볼 수 있어야 공유 링크가 의미 있고, 처음 온 사람이 가입 전에 서비스를 이해할 수 있다.

## 선택

- 비로그인 열람 가능: 중고 목록 · 검색 · 거래 상세.
- 로그인 필요: 거래 등록 · 수정 · 삭제 · 상태 변경 · [채팅하기] · 채팅 목록 · 채팅방 · 마이페이지.
- 보호 화면에 비로그인 접근 시 로그인으로 보내고 `?next=`로 돌아온다. [채팅하기]를 눌러 로그인하면 돌아와서 **버튼을 다시 눌러야** 한다 (자동으로 방을 만들지 않음 — 의도 확인).
- 인증 미들웨어는 두 모드: `requireAuth`(401) · `optionalAuth`(있으면 사용자 주입). 상세 API는 `optionalAuth`로 `viewer.isSeller` 등을 계산.

## 버린 대안

| 대안 | 장점 | 버린 이유 |
| --- | --- | --- |
| 전부 로그인 필요 | 인증 경로 하나, 판매자 정보 노출 없음 | 공유 링크 · OG · 첫 방문이 전부 로그인 벽. 웹의 장점을 버림 |
| 목록만 공개, 상세는 로그인 | 중간 | 공유 링크가 상세인데 그게 막힘. 어중간 |
| 비로그인에게 가격 · 판매자 가림 | 가입 유도 | 다크 패턴. 서비스 신뢰에 반함 |

## 트레이드오프

- 판매자 닉네임 · 아바타가 공개된다. 공개용 사용자 객체(`id, nickname, avatarUrl, createdAt`)로 제한하고 이메일은 절대 안 나간다.
- 크롤링에 노출된다. 1차 규모에선 rate limit으로 충분.
- `optionalAuth`에서 만료된 쿠키를 어떻게 다룰지(무시 vs 401) 정해야 한다 → 무시하고 비로그인으로 처리, 쿠키 삭제 헤더.

## 바뀔 가능성과 되돌리는 법
