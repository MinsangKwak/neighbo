# 결정 기록 · 왜 이렇게 했는지를 나중에 찾을 수 있게

[문서 목차](../README.md) · [00 개요](../00-overview.md)

**결정 기록은 구조에 영향을 주는 선택과 대안, 제약, 재검토 조건을 정리합니다.** 기능 범위나 운영 조건이 바뀔 때 기존 판단의 전제를 확인하고 변경 범위를 찾는 데 사용합니다.

## 언제 쓰는가

다음 중 하나면 결정 기록을 씁니다.

- 00 개요 2.4 변경 영향 매트릭스에서 **열이 3개 이상**인 결정
- 새 의존성 추가 (00 개요 "의존성 추가 규칙")
- 데이터 모델의 유니크 제약 · 삭제 정책 · 상태 기계처럼 **되돌리기 어려운** 것
- 두 사람이 다르게 판단할 수 있는 것 (한 가지 답만 있으면 기록하지 않음)

입력 길이 · 문구 · 색처럼 바꾸는 데 한 줄이면 되는 것은 [경우의 수](../cases/README.md) 표 안에서 끝냅니다.

## 형식

파일명 `NNNN-짧은-제목.md`. 번호는 만든 순서, 바꾸지 않습니다.

```markdown
# NNNN · 제목

| 상태 | 결정 YYYY-MM-DD · (대체됨 → NNNN) |
| 영향 | 2.4 매트릭스의 행 이름 · 닿는 열 |

## 맥락
무엇을 정해야 했고, 어떤 제약이 있었는가. 두세 문장.

## 선택
한 문장. 그리고 그 선택이 전제하는 것.

## 버린 대안
| 대안 | 장점 | 버린 이유 |

## 트레이드오프
이 선택에 따른 비용·제약·추가 관리 항목.

## 바뀔 가능성과 되돌리는 법
어떤 상황이 오면 이 결정을 다시 봐야 하는가. 그때 무엇을 고쳐야 하는가.
```
