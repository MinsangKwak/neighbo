# neighbo

**이웃과 중고 물건을 거래하고 채팅으로 약속을 잡는 동네 거래 서비스입니다.** 당근마켓의 핵심 흐름(목록 → 상세 → 채팅 → 거래완료)을 열 가지 기능으로 좁혀, 빈 상태 · 에러 · 권한 · 동시성까지 빠짐없이 동작하도록 명세부터 설계했습니다.

```
판매자: 가입 → 거래 등록 → (채팅 알림) → 채팅 → 거래완료 · 구매자 지정 → 마이페이지
구매자: 가입 → 목록 → 상세 → 채팅 시작 → 채팅 → 마이페이지 구매 내역
```

> **지금 단계: 명세 완료, 코드 시작 전.** 프론트엔드 · 백엔드 설계, API 계약, 데이터 모델, 트랜잭션 경계까지 문서로 닫았고, 실시간 통신은 밑바닥 스파이크로 먼저 검증했습니다. 다음은 화면 명세 → 코드입니다.

## 트러블슈팅 — 코드 전에 잡은 것 셋

**T-01 · 가끔 메시지 하나가 영영 안 보인다.** 메시지 순서와 복구 커서를 `createdAt`으로 셌는데, Postgres `now()`는 문장이 아니라 **트랜잭션 시작** 시각이다. 먼저 시작해 잠금을 기다리다 늦게 커밋된 메시지는 시각이 앞서 복구 조회에서 빠진다. → 방 행을 잠그고 방별 번호(`seq`)를 받아 "번호 순서 = 커밋 순서"를 보장. 덤으로 클라이언트가 번호 틈을 보고 스스로 채운다. [자세히](docs/troubleshooting.md#t-01) · [결정 0016](docs/decisions/0016-message-seq.md)

**T-02 · 사용자 열 명이 로그인하면 모두 `429`.** IP rate limit을 걸었지만 브라우저는 Vercel 프록시를 거쳐 오므로 백엔드가 보는 IP는 전부 Vercel 함수 하나다. → 프록시가 원 IP를 공유 비밀과 함께 넘기고, 백엔드는 비밀이 맞을 때만 그 IP를 믿는다. [자세히](docs/troubleshooting.md#t-02)

**S-04 · 화면엔 "실패", 상대에겐 도착.** 연결이 끊긴 순간 타임아웃 없이 `emit`하면 Socket.IO 버퍼에 남았다가 재연결 1.9초 뒤 몰래 전송된다는 것을 스파이크로 재현했다. → 타임아웃 있는 `emitWithAck`만 쓰고, 직접 `emit`은 lint로 막는다. [자세히](docs/troubleshooting.md#s-04)

## 역할별 입구

최상위 폴더는 `{역할}-{대표 기술}`로 지어 폴더 목록만으로 역할과 스택이 보입니다 ([결정 0015](docs/decisions/0015-folder-naming.md)).

| 역할 | 맡는 것 | 입구 |
| --- | --- | --- |
| **프론트엔드** · Next.js | 렌더링 위치 · 상태와 캐시 · 입력 처리 · 에러 화면 · 접근성 · 소켓 연결 상태 | [frontend-next/](frontend-next/README.md) → [설계 문서 7개](docs/frontend/README.md) |
| **백엔드** · Node.js | 인증 · 권한 · 데이터 제약 · 트랜잭션 · 멱등성 · 에러 코드 · 보호 장치 · 소켓 서버 | [backend-node/](backend-node/README.md) → [설계 문서 10개](docs/backend/README.md) |
| 공유 · Zod | 요청 · 응답 스키마, 입력 정규화 함수 — 두 역할이 같은 규칙을 쓰게 | `shared-schema/` (코드 단계) |

규칙은 백엔드가 강제하고, 프론트는 사용자가 그 규칙을 어기기 전에 알려 줍니다. 같은 요구사항을 두 역할이 각자 어떻게 맡는지는 [01 요구사항](docs/01-requirements.md)의 역할 열에 수용 조건마다 있습니다.

## 기술 스택

| 영역 | 선택 | 왜 |
| --- | --- | --- |
| 프론트엔드 | Next.js 16 (App Router) · TypeScript · Tailwind CSS · TanStack Query | 목록 · 상세의 서버 렌더와 OG 메타, 서버 상태 캐시 한 규칙 |
| 백엔드 | Node.js · Express · TypeScript · Prisma 7 · PostgreSQL 16 | 권한 · 트랜잭션 · 제약을 BaaS 설정이 아니라 코드로 ([0001](docs/decisions/0001-no-baas.md)) |
| 실시간 | Socket.IO | 재연결 · 룸 · ack 제공. 그 아래는 직접 만들어 본 뒤 사용 ([0005](docs/decisions/0005-socket-io.md)) |
| 인증 | JWT를 httpOnly 쿠키에, 같은 오리진 프록시 | JS가 토큰을 못 읽고, 교차 사이트 쿠키에 기대지 않음 ([0003](docs/decisions/0003-jwt-httponly-cookie.md) · [0004](docs/decisions/0004-api-proxy-same-origin.md)) |
| 검증 | Zod 공유 패키지 | 같은 규칙을 두 번 쓰지 않음, 서버가 최종 |
| 테스트 | Vitest · supertest(진짜 PostgreSQL) · Testing Library · Playwright | 수용 조건 하나에 테스트 하나 ([테스트 전략](docs/dev/TESTING.md)) |
| 배포 | Vercel(프론트) · Railway(백엔드 · DB) | [브랜치 · 배포 전략](docs/dev/BRANCHING.md) |

새 의존성은 "감추는 것 · 빼면 닿는 곳"을 적은 결정 기록 없이는 넣지 않습니다 ([개요 4절](docs/00-overview.md#의존성-추가-규칙)).

**1차 — 이번에 만드는 것**

회원가입 · 로그인 · 중고 목록 · 거래 등록 · 수정 · 거래 상세 · 거래 삭제 · 채팅 목록 · 채팅 · 마이페이지 · 채팅 알림

**1차에서 뺀 것과 이유**

| 기능 | 이유 |
| --- | --- |
| 결제 · 송금 | 거래는 "직접 만나서"가 전제. PG 연동은 범위 밖 |
| 위치 기반 검색 · 동네 인증 | 지도 API · GPS 권한이 필요하고, 핵심 흐름 완성과 무관 |
| 신고 · 차단 · 후기 | 실사용자가 없는 단계에서는 검증할 수 없는 운영 기능 |
| 이미지 메시지 · 브라우저 푸시 | 텍스트 채팅과 앱 안 알림으로 흐름을 먼저 완성 |

전체 목록은 [개요 3절](docs/00-overview.md#3-범위)에 있습니다. 기능 수를 늘리기보다 열 가지가 실패 상황까지 동작하는 것을 우선합니다.

## 라이선스와 고지

코드와 문서는 [MIT 라이선스](LICENSE)로 공개합니다.

neighbo는 당근마켓의 핵심 흐름을 참고해 만든 개인 프로젝트이며, 당근마켓(주식회사 당근)과 관계가 없습니다. 당근마켓의 상표 · 로고 · 디자인 자산은 사용하지 않습니다.
